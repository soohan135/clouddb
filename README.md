# 자기소개 포트폴리오 웹사이트

클라우드 데이터베이스 과제로 만든 개인 포트폴리오 사이트입니다.
채용 담당자나 교수님이 지원서에 첨부된 링크로 들어와 기술 스택과 프로젝트를 빠르게 확인할 수 있도록 만들었습니다.

## 화면 구성

한 페이지에 모든 섹션이 있고, 상단 메뉴를 누르면 해당 섹션으로 이동합니다.

| ID | 화면 | 내용 |
|----|------|------|
| S01 | Home | 이름, 한 줄 소개, 프로필 이미지 |
| S02 | 소개 | 전공, 관심 분야, 기술 스택, 학력 |
| S03 | 프로젝트 | 프로젝트 카드 목록, 상세 보기 모달, 더보기 버튼 |
| S04 | 연락처 | 이메일, GitHub 링크 |
| S05 | 방명록 | 작성 폼, 작성 목록 (현재 준비 중) |

## 주요 기능

### 프로젝트 상세 보기
- 프로젝트 카드의 **자세히 보기** 버튼을 누르면 모달이 열립니다.
- 모달에는 제목, 기간, 담당 역할, 사용 기술, 결과, GitHub 링크가 표시됩니다.
- 닫기 버튼, 모달 바깥 영역 클릭, ESC 키로 닫을 수 있습니다.
- 프로젝트는 최신순으로 정렬되고 한 번에 최대 6개까지 보입니다. 더 있으면 **더보기** 버튼이 나타납니다.

### 방명록 (예정)
- 이름(최대 20자)과 내용(최대 200자)을 입력해 등록하는 기능입니다.
- 지금은 정적 사이트 단계라 등록 버튼이 비활성화되어 있고, 예시 글만 표시됩니다.

## 폴더 구조

```
.
├── site/              # S3에 업로드하는 정적 파일
│   ├── index.html     # 전체 화면 (S01~S05)
│   ├── style.css      # 스타일 (모바일 대응 포함)
│   ├── script.js      # 프로젝트 데이터, 카드 렌더링, 모달
│   └── assets/        # 프로필 사진 등 이미지
├── .gitignore
└── README.md
```

## 기술 스택

- **프론트엔드:** HTML, CSS, JavaScript (프레임워크 없이 작성)
- **배포:** AWS S3, CloudFront (OAC)

## 아키텍처

```
사용자 ──HTTPS──▶ CloudFront ──OAC──▶ S3 (비공개 버킷)
```

- **S3:** HTML·CSS·JS·이미지 같은 정적 파일을 저장합니다. 버킷은 비공개로 두고 퍼블릭 액세스 차단을 켜 둡니다.
- **CloudFront:** HTTPS로 사이트를 제공하는 CDN입니다. OAC(Origin Access Control)를 통해서만 S3에 접근하므로 S3 주소로 직접 들어오는 요청은 막힙니다.

### 이후 확장 계획

| 구성 요소 | 역할 |
|-----------|------|
| Route 53 | 개인 도메인을 CloudFront 주소에 연결 |
| ACM | CloudFront용 SSL 인증서 발급 (us-east-1) |
| API Gateway | 방명록 등록 요청(`POST /api/guestbook`)을 받는 API 진입점 |
| Lambda (글 저장) | 입력값을 검사한 뒤 새 글을 S3 `guestbook/entries/`에 저장 |
| Lambda (목록 병합) | S3 이벤트로 실행되어 글을 모아 `guestbook.json`을 최신순으로 갱신하고 CloudFront 캐시를 무효화 |
| GitHub Actions + IAM | main 브랜치에 push하면 S3 업로드와 캐시 무효화를 자동으로 수행. OIDC로 역할을 받아 액세스 키 없이 배포 |

## 배포 방법

1. `site/` 폴더 안의 파일을 S3 버킷 **최상위**에 업로드합니다.
   ```bash
   aws s3 sync site/ s3://버킷이름/ --delete
   ```
2. CloudFront 배포 설정
   - 원본: `버킷이름.s3.<리전>.amazonaws.com` (웹사이트 엔드포인트가 아닌 REST 엔드포인트)
   - 원본 액세스: OAC 사용
   - 기본 루트 객체: `index.html`
3. CloudFront가 만들어 주는 버킷 정책을 S3 버킷 정책에 붙여 넣습니다.
4. 파일을 수정해서 다시 올린 뒤에는 캐시를 무효화합니다.
   ```bash
   aws cloudfront create-invalidation --distribution-id 배포ID --paths "/*"
   ```

## 로컬에서 보기

빌드 과정이 없으니 `site/index.html`을 브라우저로 바로 열면 됩니다.

## 내용 수정하기

- **프로젝트:** `site/script.js` 맨 위의 `PROJECTS` 배열을 수정합니다. `date` 값 기준으로 최신순으로 자동 정렬됩니다.
- **소개·연락처:** `site/index.html`에서 해당 섹션을 수정합니다.
- **프로필 사진:** `site/assets/profile.jpg`를 넣고, `index.html`의 `.avatar` 부분을 `<img>` 태그로 바꿉니다.
